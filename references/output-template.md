# 输出模板（Markdown 版）

成品是**一个 .md 文件**：3~5 个二级标题分节，并列项走列表，关键判断加粗，段落短、留白足。

文件里只放正文（标题行 + 正文 + 风险提示）。发布提示、字数、删改说明放聊天里，不进文件。

## 骨架

```markdown
标题：结论（≤20 字图文 / ≤30 字文章）

开头 2~3 句：第一句给结论。

## 一、位置：主跌段差不多走完

短段 ≤2 句。

短段 ≤2 句。

- **项一**：一句话
- **项二**：一句话

## 二、三个方向

短段引出。

1. **方向名** —— 是什么。适合谁，难点在哪。
2. **方向名** —— 是什么。适合谁，难点在哪。
3. **方向名** —— 是什么。适合谁，难点在哪。

短段：明确反对的那一条。

## 三、什么时候动手

短段。

1. 已经提示过的动作
2. 最稳的做法 + 等什么信号
3. 时间窗

## 四、几条红线

- **别止损** —— 一句话理由
- **别盲目抄底** —— 一句话理由

一句话收尾。

以上内容仅为直播观点的整理，不构成任何投资建议，据此操作风险自担。
```

节数 **3~5 节**，每节 **不超过 3 段 + 1 个列表**。

## 语法使用规范

| 用途 | 语法 | 约束 |
|---|---|---|
| 分节 | `## 一、xxx` | ≤14 字，不带句号，3~5 个 |
| 并列方向 / 步骤 | `1.` `2.` `3.` | 3 项以上才用；每项 ≤2 行 |
| 并列要点 / 板块 | `- ` | 每项一句话 |
| 关键判断 | `**` | 全文 8~12 处，每节 2~3 处；整句加粗 ≤3 |
| 作者原话 | `> ` | 最多 1 处 |
| 表格 / 分隔线 / 代码块 / 嵌套列表 | 禁用 | 抖音渲染不了 |

**加粗只给这四类**：列表项名称、方向名、反对项、纪律红线。段落里的整句加粗封顶 3 处，其余只加粗短语。

## 各节写法

### 开头（30 字内出结论）

不写"最近市场震荡加剧"这种铺垫。

```
政策底已经出来了，市场底还没确认。他这次的态度很明确：**不悲观了**。

现在的位置，他说很像 7 月 24 号那一周，主跌段差不多走完。
```

### 一、位置与定调

讲清：现在什么位置、凭什么这么判断、反弹还是反转。

作者的私人口径要留（"指数波动不超 2% 就不叫大跌"），这类标准比结论更有用。

### 二、方向

有编号框架的放这节，**一律用有序列表**，每项格式固定：

```
1. **方向名** —— 是什么。适合谁；难点是什么。
```

三项平铺写成大段，就糊成一团，这是最容易丢分的地方。

**明确反对的项单独成段，并加粗：**

```
**高股息不要再追了。** 很多卖方报告现在都在推高股息，他的看法正好相反。
```

### 三、节奏

有序列表天然适合写时点：已提示的动作 → 等什么信号 → 时间窗。

条件判断必须保留条件："如果出现加速下跌，反而是可以动手的位置"——不能写成"可以动手"。

### 四、红线

无序列表，每项一句话，加粗放在红线名上。

```
- **别急着止损** —— 科技都跌到这个位置了，止损要亏多少
- **别盲目抄底** —— 三个问题解决不了：是不是底、是第几层底
```

## 发布提示模板（放聊天里，不进文件）

交付时附这一段，帮用户把 Markdown 套成抖音原生格式：

```
发布时二选一：

A. 用 Typora / VS Code 预览这个 md，全选复制富文本，直接粘进抖音编辑器（多数情况格式能带过去）。

B. 带不过去就手工套，不费事：
   · 4 个「## 」行 → 设为二级标题（删掉 ##）
   · 有序列表 → 设为有序列表（删掉 1. 2. 3.）
   · 无序列表 → 设为无序列表（删掉 - ）
   · 6 处 ** 加粗 → 选中文字加粗（删掉 **）
```

## 篇幅分配（800 字参考）

- 标题 + 开头：80 字
- 位置：180 字
- 方向：300 字
- 节奏：120 字
- 红线：80 字

任何一节超了，先砍形容词和重复安抚，再砍"看不懂的细节"。

## 发布前最后一步

- 打开 .md 预览，看层级是否清楚、有没有超过 3 行的段落
- 数一遍加粗，超过 8 处就删
- 确认没有表格、`---`、代码块
- 首屏能不能看到结论
